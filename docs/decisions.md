# Architecture decisions

| # | Decision | Why | Status |
|---|---|---|---|
| 0001 | **New repo `trackwell`**; legacy repos untouched | Pushing legacy `main` deploys production; the legacy apps must keep running until Trackwell is validated | Accepted (user) |
| 0002 | **React 19 + TS + Vite 8 + Tailwind v4** (build-time), one npm package with clear folders (`src/domain`, `src/app`, `worker`, `migrations`) instead of workspaces | Continuity with the legacy stack; workspaces add nothing for one app | Accepted |
| 0003 | **Pure domain package**: all money and dates live in `src/domain` with no React or I/O; integer cents | Deterministic, testable, shared by UI, Worker and AI tools | Accepted |
| 0004 | **DST-safe pay periods**: whole-calendar-day arithmetic via `Date.UTC` | Legacy grouped period-start Mondays into the previous period during DST. Stored dates and pay are unchanged (tested). | Accepted (user brief) |
| 0005 | **Payday = period end + 5 days**, configurable | The literal "second Friday after period end" (+12) matched none of the real payments; +5 matched the cycle for 39/40, amounts within 5% for 29/40, with 0 payments lacking work. The user chose the data-verified rule. | Accepted (user) |
| 0006 | **Legacy oracle**: byte-identical copies of the legacy pay and recurring code, used only by parity tests | Proves "preserve the existing rules" mechanically: 756-combination pay grid, every date 2024–2027 | Accepted |
| 0007 | **WorkDay is the pay unit; coverage blocks carry no money** (type-level and DB-level) | Multiple Coverage must never multiply daily pay | Accepted |
| 0008 | **Cloudflare D1**, record-level tables, `(source, legacy_id)` unique keys, soft deletes, audit log, write-once legacy archive | Avoids whole-document overwrites (legacy D2); idempotent import; preserves retired data | Accepted (user) |
| 0009 | **Custom single-admin auth**: PBKDF2-SHA256 (100k, the Workers maximum) via WebCrypto; random 256-bit session tokens stored hashed server-side; `__Host-` HttpOnly Secure SameSite=Strict cookie; 12h idle / 7d absolute expiry; revocation; per-IP and global login lockout; CSRF via Origin/Fetch-Metadata check plus a per-session token header | Replaces the legacy password-in-cookie design; no Cloudflare Access by user decision | Implemented (Phase 3, D1-backed) |
| 0010 | **Worker serves the SPA** (static assets), sets security headers; no public GitHub Pages copy | Fixes legacy S4/S9 (stripped CSP, public origin) | Implemented in local config (assets + security headers); deployment pending approval |
| 0011 | **Bell schedules are data** (`BellSchedule`, weekday rules, date overrides, lunch variants, split periods); MHS times `pending-reference` until the official image | Configurable; no guessing | Implemented; MHS 2026–27 verified against the official image (Phase 3) |
| 0012 | **No shadcn/ui or React Hook Form yet**: native elements plus a few owned primitives (radiogroup, menu, sheet) | Phase 2 has no forms; avoids dependency bloat. RHF + Zod arrive with CRUD in Phase 3. | Accepted |
| 0013 | **Recharts behind one wrapper** (`TimeBars`) plus `BarList` instead of pies; table view for every chart | dataviz rules: one axis, line form for state, accessible alternative | Accepted |
| 0014 | **Pages lazy-loaded** | Charts chunk (≈121 KB gz) loads only with chart pages | Accepted |
| 0015 | **Synthetic data only in Phase 2**, deterministic and seeded, money derived through the real engine; `?data=` toggle for empty/one/worst-case/loading/error | Privacy; break-ui states; labeled in the UI | Phase 3: production builds use the real API only; `?data=` demo states are development-only |
| 0016 | **Read-only snapshot + record-level writes**: one `GET /api/v1/snapshot` (a single D1 batch) for reads; every write is per record | Small single-user dataset; one consistent read; no whole-dataset saves (legacy D2) | Implemented |
| 0017 | **Optimistic concurrency** via `updatedAt`; coverage inserts guarded by the parent's version inside the same batch | A stale tab can't overwrite newer data, and a failed update can't half-apply | Implemented |
| 0018 | **Shared earnings model** (`earnings.ts`): outstanding = upcoming + overdue unpaid pay periods; legacy formula kept as a reconciliation check | One number everywhere; legacy behavior still inspectable | Implemented |
| 0019 | **Bell schedules stay in versioned code**; D1 holds schedule ids (for FKs) and per-date overrides | Times are reviewed data with a reference test, not user-editable rows | Implemented |
| 0020 | **Soft delete + archive**: work days, payments, expenses, recurring plans soft-delete; categories and payment methods archive; deleted recurring occurrences become skips | Nothing is lost; history keeps its labels | Implemented |
| 0021 | **Import SQL uses `ON CONFLICT DO NOTHING`, never `INSERT OR IGNORE`** | `OR IGNORE` silently drops CHECK/FK violations; an import must fail loudly | Implemented |
| 0022 | **Rem-based type, root 100%** | Respects the browser's default font size (break-ui decision) | Implemented |
| 0023 | **Chart outlier capping** with the outliers named in words; table keeps exact values | One extreme value no longer flattens the chart (break-ui decision) | Implemented |
| 0024 | **Wide screens**: content column up to 1760px | Uses wide displays for charts and tables (break-ui decision) | Implemented |
| 0025 | **Assistant runs server-side on Cloudflare Workers AI**, model `@cf/ibm-granite/granite-4.0-h-micro` (configurable via `AI_MODEL`) | Cheapest current Workers AI text model with function calling ($0.017 / $0.112 per M tokens in/out, 131k context; checked 2026-11-20). `qwen3-30b-a3b-fp8` is deprecated from 2026-11-20; `glm-4.7-flash` is the free-plan fallback. No API keys: the Worker binding | Implemented; genuine inference needs `wrangler login` + `npm run dev:api:ai` |
| 0026 | **Mock mode by default** (`AI_MODE=mock`): a rule-based stand-in replaces only language understanding; tools, validation, drafts and confirmation are real. Workers AI runs only with an `[ai]` binding AND `AI_MODE=workers-ai` | Tests stay offline and free; paid inference can never switch on silently | Implemented |
| 0027 | **Model proposes, server decides**: the model forwards words to four tools; dates, periods, defaults, teacher matches, validation and pay are deterministic server code; a successful run ends as a PENDING `ai_drafts` row | Money and records never depend on model output | Implemented |
| 0028 | **Confirmation is a separate endpoint** with an atomic `pending → confirmed` claim, reuse of `createWorkDay`, release on failure, and read-back verification | Prevents duplicate saves (double click, replay) and makes "saved" a checked fact | Implemented |
| 0029 | **Finance Q&A sends only the question to the model**; totals come from fixed parameterized SQL and a template | No records or amounts reach the provider; no model-written numbers | Implemented |
| 0030 | **Weekday defaults are history-preserving rows** (`weekday_defaults`, effective from the edit date) | Editable without rewriting the past; saved days never change | Implemented |
| 0031 | **GLM 4.7 Flash is the default model**; Granite is for manual tests only; no automatic fallback | Genuine runs: GLM 5/5 eval cases; Granite dropped a period in 1 of 2 runs. Still within the free allocation (≈50 Neurons per entry) | Implemented (user-approved 2026-11-20) |
| 0032 | **Deterministic cross-check of drafts against the request wording** | Catches omitted, duplicated or misassigned periods that schema validation can't | Implemented |
